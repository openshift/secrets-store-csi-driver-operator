## Summary

Read-only review of CSV annotations in
`config/manifests/stable/secrets-store-csi-driver-operator.clusterserviceversion.yaml`.

## Current Values

```yaml
features.operators.openshift.io/token-auth-aws: "false"
features.operators.openshift.io/token-auth-azure: "false"
features.operators.openshift.io/token-auth-gcp: "false"
```

## Analysis

With SSCSI-254, the operator now supports configuring WIF audiences through the
`ClusterCSIDriver.spec.driverConfig.secretsStore.tokenRequests` API. This means:

- **AWS STS**: Users can set `audience: "sts.amazonaws.com"` → token-auth-aws annotation
  could be updated to `"true"`
- **Azure AD**: Users can set `audience: "api://AzureADTokenExchange"` → token-auth-azure
  could be updated to `"true"`
- **GCP IAM**: Users can set `audience: "https://iam.googleapis.com/<workload-pool>"` →
  token-auth-gcp could be updated to `"true"`

## Decision

**Annotation update is NOT in scope for SSCSI-254 implementation**. It requires:
1. PM/AOS storage team decision on whether configuring audiences in the operator CR
   constitutes "token auth support" per the OLM annotation semantics
2. A separate PR and release note (annotation changes are customer-visible)
3. Verification that the CSI driver itself (not just the operator) handles the
   WIF token exchange end-to-end before advertising `token-auth-aws: "true"` etc.

## Action

No CSV changes made in this task. A follow-up should be tracked as a separate ticket
after SSCSI-254 implementation is merged and tested:

> **Follow-up**: Evaluate updating `token-auth-{aws,azure,gcp}` annotations from
> `"false"` to `"true"` in CSV once SSCSI-254 WIF support is validated end-to-end
> in a release candidate. Assign to PM + AOS storage team for decision.
