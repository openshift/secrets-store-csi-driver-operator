## Findings

### A-001: Rotation Interval Field (RESOLVED — with structural surprise)

The actual API structure is **more nested** than `specs.md` described. The `rotationPollIntervalSeconds` field is NOT directly in `SecretsStoreSecretRotation` — it is in the `Custom` variant:

```go
// SecretsStoreSecretRotation
type SecretsStoreSecretRotation struct {
    Type   SecretRotationType    // "None" | "Custom"
    Custom CustomSecretRotation  // only valid when Type == "Custom"
}

type CustomSecretRotation struct {
    RotationPollIntervalSeconds int32  // field name (PR #2906 may rename to minimumRefreshAge)
}
```

**Go access path for rotation interval:**
```go
spec.DriverConfig.SecretsStore.SecretRotation.Custom.RotationPollIntervalSeconds
```

**To disable rotation:** set `secretRotation.type = "None"` (default when omitted).
**To enable rotation:** set `secretRotation.type = "Custom"` with optional `custom.rotationPollIntervalSeconds`.

**PR #2906 impact:** If it renames `rotationPollIntervalSeconds` → `minimumRefreshAge`, only the `CustomSecretRotation` struct changes. The outer type discriminator pattern stays the same.

### Q4: CEL Immutability (CONFIRMED)

Present at line 26 of `types_csi_cluster_driver.go` (object-level validation on `ClusterCSIDriver`):

```
rule: "oldSelf.spec.?driverConfig.?secretsStore.?tokenRequests.?type.orValue('') != 'Managed'
       || self.spec.?driverConfig.?secretsStore.?tokenRequests.?type.orValue('') == 'Managed'"
message: "tokenRequests type cannot be changed from Managed"
```

Once `tokenRequests.type = "Managed"` is set, it **cannot be changed back** (Managed → Unmanaged is rejected by API). This aligns with FR-006.
