## Design Notes

**Why chained (not inline swap):** The acceptance criterion requires `csidriver.yaml` absent from the original file list. Chaining a second `WithConditionalStaticResourcesController` gives `csidriver.yaml` its own named controller (`SecretsStoreCSIDriverController`) making it visible in events and logs, while reusing the exact same lifecycle predicates (Managed/Removed) as the original.

**`csiDriverAssetFunc` scope:** `clusterCSIDriverLister` is in scope at the call site — it was constructed in T2_2 as `dynamicInformers.ForResource(gvr).Lister()` immediately before the `csiControllerSet` builder.

**Lifecycle preservation:** Both controllers use `getOperatorSyncState(operatorClient) == opv1.Managed` for creation and `== opv1.Removed` for deletion. The CSIDriver is created and deleted on the same conditions as before.
